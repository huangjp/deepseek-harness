# Agent Note: MiniMax quota window wait

Status: implemented

[English](2026-11-18-minimax-quota-window-wait.md) | 中文

## Problem

MiniMax 的 Anthropic 兼容 Messages 路由在两种情况下都返回 HTTP 429：短时请求速率用尽，以及套餐窗口用尽。短时情况大约一分钟内可以再用。套餐情况要么是 5 小时窗口，要么是共享的周窗口，MiniMax 的用量规则写明额度在该窗口结束时恢复。窗口从第一次使用起算。MiniMax 文档中的 429 体，以及代码 2056 和 2067 上观察到的体，带有套餐用语和错误码。它们不带 `Retry-After`，也没有恢复时刻。pi-ai 只保留 `error.message`，因此响应头到不了 harness。

普通重试策略把 429 当成 `RATE_LIMIT`，最多睡十秒，五次之后放弃。套餐窗口因此会结束回合。用户得回来手动继续任务。模型路由的熔断把两次失败记下来，然后把路由跳过五分钟。对持续数小时或一周的窗口，这是错误的时钟，它也不会让进行中的步骤活着。

## Decision

`QUOTA_WINDOW` 是会恢复的窗口的提供方中立 code。`RATE_LIMIT` 仍是短时限制，`QUOTA` 仍是本等待不视为可恢复的余额。MiniMax 在共享的 pi-ai 映射之前，把 2056、2067 和套餐用语分类为 `QUOTA_WINDOW`。错误码 1002 和 2062，以及文档中的 RPM/TPM/并发文本，留在那张映射上，因此仍走 `dsh-llm-retry`。

`dsh-llm-quota-wait` 在短重试策略之后监听 `agent/request-error`。对 `QUOTA_WINDOW`，它询问 `llm/quota-window`。MiniMax 用用量时钟回答：在 API 主机上 `GET /v1/token_plan/remains`，然后是 coding-plan 路径；配置的主机名以 `api.` 开头时再加上 `www` 主机。`end_time` 是 5 小时窗口，`weekly_end_time` 是周窗口。文本模型两个都要有余量；两个都用尽时，周窗口的结束时刻才是约束，因为 5 小时恢复不会补回周额度。步骤睡到该时刻再加两秒，在睡眠前追加带有绝对恢复时刻的 `llm/quota-wait`，然后重试同一步骤。取消就是回合的中止信号。

当时钟缺失、已经过去，或远于八天时，等待从一分钟起探测，加倍到十五分钟。它不去发明一个墙上时钟的 5 小时边界。探测就是重试的模型请求。睡眠由一个计时器完成，延迟长于平台上限时拆成若干段。

进行中的步骤总会等待，包括会话的路由模式是 auto 的时候，因为步骤的模型选择已经固定，循环不会在步骤内部更换提供方。固定模式是同一种等待。之后的自动路由认领会跳过这条路由直到 `resumeAtMs`，因为插件发出 `llm/quota-hold`。`QUOTA_WINDOW` 不增加路由的失败计数，因此五分钟冷却不会取代这个窗口。其他提供方的接入方式是发出 `QUOTA_WINDOW`，并且在能做到时回答 `llm/quota-window`。

## Alternatives considered

**把 `retryPolicy.maxDelayMs` 拉到一周。** 短重试预算、五次上限和十秒默认值是为 `RATE_LIMIT` 和传输失败准备的。套餐窗口是另一种失败，它会花掉那份预算，或在 `Retry-After` 超过 `maxDelayMs` 时被拒绝。

**把进行中的自动路由步骤故障转移到另一条路由。** 步骤在请求前就捕获了模型选择，`agent/request` 不允许改它。让回合失败、好让下一条用户消息改道，会丢掉用户已经开始的任务。之后的认领仍然可以通过暂停转到别处。

**按墙上时钟去猜下一个 5 小时边界。** MiniMax 的每个窗口从第一次使用起算。从纪元推出来的边界可能偏离真实恢复时刻数小时。

**进程重启后恢复这次等待。** 恢复会话会在任何插件运行之前，把未结束的回合以 interrupted 关闭。重新打开那个回合会是一套新的 agent 循环生命周期。已经提交的工具结果还在；等待不会继续。

## Consequences

碰到套餐窗口的 MiniMax 会话会停在同一个回合上，直到窗口打开或用户取消。短时 429 仍走快速重试。还没开始的自动路由工作可以在整个窗口内使用另一条规则，而不是只冷却五分钟。代价是一个长期留在进程里的计时器，以及当时钟缺失时那些会计费的探测请求。重启仍然会结束未完成的回合，用户之后再继续它。
